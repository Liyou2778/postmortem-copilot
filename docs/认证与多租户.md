# M10.6：本地认证、RBAC 与团队多租户

> 上线：2026-11-23 20:44 CST  
> 模式：本地账号 + API Key（用户选择，不接外部 IdP）  
> 生产：K8s 2 副本；公网 `:8000` 需要登录或 API Key

---

## 1. 角色与租户

| 角色 | 权限 |
|---|---|
| `viewer` | 只读：任务/证据/报告/CMDB 页面 |
| `operator` | 创建/运行/规划/租约/恢复/执行 |
| `tenant_admin` | operator + 租户内用户/API Key + 管理页 |
| `platform_admin` | 全局：所有租户、租户/用户/Key 管理、Basic Auth 管理页 |

租户是显式实体（如 `team-core`）。用户属于一个租户；API Key 也绑定租户。

---

## 2. 认证方式

### 浏览器

- `/login` 用户名/密码登录；
- 成功设置 HttpOnly + SameSite=Lax Cookie `copilot_session`；
- 会话 token 仅存 SHA-256 哈希，默认 12 小时过期；
- 未登录 HTML 请求重定向 `/login`，API 返回 401。

### API / CI

```http
X-API-Key: cpk_...
```

或：

```http
Authorization: Bearer cpk_...
```

创建：

```http
POST /api/v1/admin/api-keys
Authorization: Bearer <session-token>
{"name":"ops-ci","tenant_id":"team-core","role":"operator"}
```

原始 Key 只返回一次；数据库只存哈希。

---

## 3. 任务租户隔离

- `TASK_CREATED` 事件写入 `tenant_id`；
- `TaskView.tenant_id` 从事件投影；
- HTML/API 任务路径由中间件检查：
  - 同租户可访问；
  - 跨租户返回 404（不泄露存在性）；
  - `platform_admin` 例外；
- 旧任务没有 tenant，投影为 `default`，只有 platform admin 可见。

已验证：

```text
team key -> own task: 200
team key -> platform task: 404
platform token -> team task: 200
anonymous task: 401
```

---

## 4. 速率限制与 CSRF

- DB 固定窗口 `(identity, minute)`，多副本共享，默认 120 次/分钟；
- 超限 429；
- viewer 写操作 403；
- 登录表单使用服务端签名 `csrf_token` + 双提交 Cookie；缺失/错误返回 403；
- `/admin` 的 session Cookie POST 校验 `Origin` 与 Host 同源；
- Basic Auth 保留为 bootstrap 管理通道，不作为普通用户会话；
- 管理页/CMDB 写表单尚未逐表单加 CSRF token，列为 PRD 例外。

## 7. 完整 OIDC 授权码流程（已联调）

已实现：

```text
GET /api/v1/auth/oidc/login
  -> state + nonce 签名 Cookie
  -> 302 到 IdP authorization_endpoint

GET /api/v1/auth/oidc/callback
  -> 校验 state
  -> code 换 token
  -> JWKS 验签 id_token（iss/aud/exp/iat/nonce）
  -> preferred_username/email/sub 映射到本地 app_user
  -> 创建本地 session Cookie
```

配置在 `/opt/copilot/.env.oidc`（0600）：

```dotenv
OIDC_ISSUER=http://8.136.102.215:8080/realms/copilot
OIDC_CLIENT_ID=postmortem-copilot
OIDC_CLIENT_SECRET=...
OIDC_REDIRECT_URI=http://121.41.224.245:8000/api/v1/auth/oidc/callback
```

已用 Keycloak 26.0.8 联调通过：

```text
app login: 302 -> Keycloak
Keycloak login page: 200
callback -> app: 200
/api/v1/auth/me: 200
username=sso-test, tenant=team-core, role=operator
OIDC_FLOW_OK
```

### 临时 HTTPS

为了验证 HTTPS 形态，又在 Keycloak ECS 上加了 Serveo 临时隧道：

```text
https://53330eddb4407d49-8-136-102-215.serveousercontent.com
```

Keycloak 重启为：

```text
KC_HOSTNAME=https://<serveo-url>
KC_PROXY_HEADERS=xforwarded
数据卷：keycloak-data（H2 持久化）
```

应用 OIDC issuer 切到该 HTTPS URL 后，真实登录再次通过：

```text
app login: 302 -> https://...serveousercontent.com/...
Keycloak login page: 200
after login: 200 -> app
/api/v1/auth/me: 200
username=sso-test
OIDC_FLOW_OK
```

**这是临时 HTTPS 联调**：Serveo 免费隧道 URL 会变化，不能当生产域名。
目前已经按用户决定回退到稳定的 **HTTP dev**：

```text
OIDC_ISSUER=http://8.136.102.215:8080/realms/copilot
OIDC_REDIRECT_URI=http://121.41.224.245:8000/api/v1/auth/oidc/callback
```

Keycloak 仍是 `start-dev` + H2，生产还需要正式域名、HTTPS 证书、
PostgreSQL/MySQL、备份和密钥轮换。

## 8. SSO（可信反向代理模式，备选）

适合企业已有 IdP（Keycloak/Azure AD/Okta）但不想在应用里解析 OIDC token 的部署：

```text
浏览器 -> oauth2-proxy / ALB OIDC -> 注入 X-Auth-Request-User
                              + X-Auth-Proxy-Secret
        -> copilot /api/*
```

配置：

```dotenv
AUTH_TRUSTED_HEADER=X-Auth-Request-User
AUTH_TRUSTED_SECRET=<long-random>
```

约束：

- 代理必须删除客户端自带的同名 header，并设置共享 secret；
- `AUTH_TRUSTED_SECRET` 为空时该路径禁用；
- SSO 用户名必须已存在于 `app_user` 且 `active=1`，角色/租户来自本地 RBAC；
- 不隐式建号，避免伪造 header 直接获得 `platform_admin`；
- 测试：`principal_for_username` 覆盖已有/不存在用户。

## 9. 边界（未完成部分）

- **OIDC 生产化**：当前 Keycloak 是 `start-dev` + HTTP + 容器内 H2，
  不是持久化生产 IdP；需要 HTTPS、数据库、备份、反向代理和 secret 轮换；
- **SSO 备用模式**：可信反向代理 header 仍保留，适合已有 oauth2-proxy/ALB 的部署；
- SSO/OIDC 用户必须先在本地 `app_user` 存在并绑定 tenant/role，不做隐式建号；
- **CMDB/目录目前是平台级**：CMDB 的 CI/变更没有按 tenant 隔离；
- **报告归档 OSS 前缀**：新任务写入 `postmortems/tenants/<tenant>/<task>/...`；
  旧任务仍保留历史 `postmortems/<task>/...` 路径（没有迁移历史对象）；
- 登录表单已有 CSRF token；管理页/CMDB 写表单仍只做同源校验；
- 没有短信/邮件找回密码、MFA；
- `app_session` 未做主动撤销列表（logout 只清 Cookie）。

这些是 M10.6 后续增量，不应在 PRD 100% 验收时声称已完成。
