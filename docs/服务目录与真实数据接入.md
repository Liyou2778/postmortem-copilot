# 服务目录与真实数据接入（M8）

> 项目：P1 Postmortem Copilot
> 落地时间：2026-11-22
> 关联：`P1-PRD.md` FR-3 / FR-7、`docs/生产部署记录.md`

---

## 1. 为什么做这件事

在 M8 之前，工具层有两种模式：

| 模式 | 行为 | 问题 |
|---|---|---|
| `TOOL_BACKEND=local` | 进程内 fixture | 报告里的“证据”全是合成的，无法证明系统真能查生产数据 |
| `TOOL_BACKEND=mcp`（旧） | stdio 连 6 个 MCP server，但上游统一指向 `DEVSTACK_URL` | 协议层是真的，数据仍是 mock；且 `PROMETHEUS_URL` 没有真正生效 |

M8 要解决的不是“再写一个页面”，而是把下面这条链路做成可审计的：

```
告警/页面 → Orchestrator → 服务目录（service + 证据类型）
          → 数据源绑定（URL / selector / metric / real|mock）
          → MCP server → 真实 Prometheus / devstack
          → Evidence(data_mode=real|mock|fixture) → 报告标黄
```

三个硬要求：

1. **真实数据要真查**：Prometheus 用标准 `/api/v1/query_range` 语义（`start/end/step`），不是 devstack 的 `window` 兼容参数。
2. **查不到就失败**：服务没有绑定、绑定停用、数据源停用，一律返回“不可得”，不允许偷偷回退到别的租户或 mock。
3. **Mock 必须标黄**：Mock 数据源只能绑定成 `mode=mock`，真实数据源只能绑定成 `mode=real`，否则写入直接拒绝；报告、证据页、长期记忆三处都做门禁。

## 2. 架构与职责

```
┌──────────────┐    service+kind     ┌────────────────┐
│ Orchestrator │ ──────────────────► │ CatalogRouter  │
│  (agents)    │                     │ resolve()      │
└──────────────┘                     └───────┬────────┘
                                             │ datasource_url / selector /
                                             │ metric / data_mode
                                     ┌───────▼────────┐
                                     │ MCPGateway     │ 6 个 stdio server
                                     └───────┬────────┘
                     ┌───────────────────────┼───────────────────────┐
                     ▼                       ▼                       ▼
              prometheus MCP           loki/cmdb/deploy MCP      ticket/kb
                     │                       │
                     ▼                       ▼
        http://127.0.0.1:9090      http://127.0.0.1:9101
        （真实 node_exporter）       （devstack，Mock）
```

边界：

- **CatalogRouter 不解析数据**，只做“服务 → 数据源”的解析和参数注入。
- **MCP server 不决定服务身份**，只执行查询并原样标注 `data_mode`。
- **Agent 不直接拼 URL**，所有证据必须经过 catalog；没有绑定就没有证据。
- **Catalog 不存密钥**，只存 base URL；凭据留在各 MCP 进程的环境变量。

## 3. 数据模型

三张表，SQLite 与 MySQL 共用一份 MySQL 兼容 DDL（`db.CATALOG_DDL`）：

### `datasource`

| 字段 | 说明 |
|---|---|
| `name` | 唯一名，如 `ecs-prometheus` / `devstack` |
| `kind` | `prometheus` / `loki` / `cmdb` / `deploy` / `kb` / `multi` |
| `base_url` | 只允许 http(s)，host 必须在 `TOOL_URL_ALLOWLIST` |
| `mock` | 1 = Mock 数据源 |
| `enabled` | 停用后所有绑定不可解析 |

### `service_catalog`

服务身份与责任人：`name`、`display_name`、`owner`、`tier`、`description`、`enabled`。

### `service_binding`

| 字段 | 说明 |
|---|---|
| `(service_name, kind)` | 主键，每类证据最多一个数据源 |
| `datasource_name` | 指向 `datasource` |
| `selector` | PromQL / Loki 标签选择器，如 `service="ecs-copilot"` |
| `metric` / `secondary_metric` | 指标类主/辅指标 |
| `mode` | `real` / `mock`，**必须与数据源 `mock` 一致** |

`resolve(service, kind)` 用三表 join + `enabled=1` 过滤；没有行就返回 `None`。

## 4. 路由规则（fail-closed）

`CatalogRouter.call()` 对每个带 `service` 参数的工具调用：

1. 按 server 前缀映射证据类型（`prometheus.*` → `prometheus`）。
2. `resolve(service, kind)`：
   - 无绑定 → `ToolResult(ok=False, error="服务目录未配置 ...")`，**不发起任何网络请求**。
   - 有绑定但数据源/绑定停用 → 同上。
3. 用 `assert_url_allowed` 再做一次 SSRF 白名单校验（目录写入时已校验，这里是纵深防御）。
4. 注入 `datasource_url`、`data_mode`；指标类再注入 `selector` 与 `metric`。
   - 主指标：`slot=primary`（默认）
   - 辅指标：`slot=secondary`，未配置则失败，Agent 跳过而不是编一个指标。
5. 结果返回后 `setdefault("data_mode", binding.mode)`；若 MCP server 已降级为 fixture，保留更强的 `fixture` 标记。

### 为什么“没有绑定”不 fallback

多租户平台里，fallback 到默认 Prometheus 等于**用错租户的数据回答当前服务的问题**。这比“没有数据”危险得多。因此宁可让某次分析只有一部分证据，也不让错误证据进入报告。

## 5. 真实 Prometheus 查询

`services/mcp_servers/prometheus.py` 的关键变化：

| 旧行为 | 新行为 |
|---|---|
| 固定查 `latency_p99_ms` | metric 由服务目录注入（`ecs-copilot` 用 `node_load1`） |
| `?query=...&window=30m` | `?query=...&start=<unix>&end=<unix>&step=<秒>` |
| 上游失败也返回 fixture，但只标 `source=fixture` | 额外标 `data_mode=fixture`，且“可达但无样本”返回 `points: [] + no_data: true`，**不再伪造数据** |
| 单方向阈值 `peak > baseline*1.5` | 双向 + 绝对位移裁决（见下） |

异常判定：

- baseline = 窗口前 1/3 的中位数；
- 上/下变化各自要求相对变化 ≥ 50%；
- 两个方向都满足时，选**绝对位移更大**的方向；
- baseline 小于 0.5 时不输出百分比（避免 `0.01 → 7.25` 打印 `72400%` 这种噪声），只给绝对 `delta`。

> 这个规则来自一次真实误报：ECS 负载 `0.01 → 6.7` 的演练里，`0.01 → 0` 的小抖动因为有“无限相对跌幅”被判定成主异常，真正的高负载反而被盖住。修复后加了回归测试 `test_tiny_baseline_spike_beats_infinite_relative_drop`。

## 6. 管理页面与 API

### 页面（Server-side Render，无 JS 构建）

| 路径 | 作用 |
|---|---|
| `/admin/catalog` | 服务列表 + 新增服务 |
| `/admin/catalog/{name}` | 服务信息、五类证据绑定、覆盖/删除 |
| `/admin/datasources` | 数据源注册表 + 新增 |
| `/admin/datasources/{name}/test` | 连通性测试（真实 Prometheus 查 `up`；Mock 查 `/healthz`） |

### JSON API

| 方法 | 路径 |
|---|---|
| GET | `/api/v1/catalog/services`、`/services/{name}` |
| PUT/DELETE | `/api/v1/catalog/services/{name}` |
| PUT/DELETE | `/api/v1/catalog/services/{name}/bindings/{kind}` |
| GET | `/api/v1/catalog/datasources` |
| PUT/DELETE | `/api/v1/catalog/datasources/{name}` |
| POST | `/api/v1/catalog/datasources/{name}/test` |
| GET | `/api/v1/catalog/resolve?service=&kind=` |

所有 `/admin/*` 与 `/api/v1/catalog/*` 都走同一个可选 HTTP Basic Auth：`ADMIN_USER` / `ADMIN_PASSWORD`。密码为空时明确关闭（只适用于本机演示），生产必须设置。

> 生产验证时发现过一个问题：页面加了鉴权，但 JSON 读接口漏了。已用 router-level dependency 修复，并复测无认证返回 401。

## 8. 已知限制与下一步

| 限制 | 说明 | 下一步 |
|---|---|---|
| 只有 Prometheus 是真实源 | Loki / CMDB / 变更仍是 devstack，报告已强制标黄 | 接真实 Loki / CMDB / 发布系统 |
| 每次分析新建 6 个 MCP 子进程 | 峰值内存可控（实测无泄漏），但启动有开销 | 改成进程级共享 `MCPGateway`，带健康检查 |
| 目录放在主库 | 与业务表同库，单实例 | 规模上来后独立 CMDB 服务 |
| Basic Auth 无 CSRF token | 内网/演示够用 | 接 SSO / 网关鉴权，加 CSRF |
| 没有按服务限流 | `TOOL_RATE_LIMIT_PER_MIN` 目前只对 local registry 生效 | 在 MCP server 侧加令牌桶 |
| 指标异常检测是规则型 | 对 counter 类指标不适用 | 目录里声明 metric 类型，counter 走 rate |

## 9. 复现命令

```bash
# 真实 Prometheus 连通性（ECS 本机）
curl -s http://127.0.0.1:9090/api/v1/query --get \
  --data-urlencode 'query=node_load1{service="ecs-copilot"}'

# 目录解析
curl -u admin:*** http://127.0.0.1:8000/api/v1/catalog/resolve \
  '?service=ecs-copilot&kind=prometheus'

# 触发一次真实指标分析
TASK=$(curl -s -X POST http://127.0.0.1:8000/api/v1/tasks \
  -H 'content-type: application/json' -d '{"title":"验收"}' | python -c 'import json,sys;print(json.load(sys.stdin)["task_id"])')
curl -s -X POST "http://127.0.0.1:8000/api/v1/tasks/$TASK/run" \
  -H 'content-type: application/json' -d '{"service_name":"ecs-copilot","window":"10m"}'
```
